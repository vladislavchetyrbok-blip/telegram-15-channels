# Аудит существующей ежедневной системы Зодиака

**Статус:** Выполнено (Package 91)
**Дата:** Июнь 2026

## Обзор
Модуль Зодиака имеет уже настроенную ежедневную систему публикаций. Ранее была проделана большая работа по настройке генерации, dry-run проверок и безопасного апрува контента перед отправкой в Telegram.

Создана новая страница в дашборде: `/dashboard/networks/zodiac/daily-system`.

## Найденные компоненты:
1. **Конфиг каналов:** `data/zodiac-channels.json` (определяет 13 каналов)
2. **Генерация:** `scripts/generate-zodiac-plan.mjs` (создает ежедневные и недельные посты, совместимость)
3. **Хранилище контента:** `data/zodiac-daily-plan.json` (хранит результаты генерации до публикации)
4. **Ledger публикаций:** `data/zodiac-ledger.json` (учитывает pending/sent статусы постов, предотвращает дубли)
5. **QA и статус:** `scripts/zodiac-status.mjs` (анализирует готовность)
6. **Автоматизация:** `.github/workflows/zodiac-scheduler.yml` (ежедневный крон)

## Команды (CLI API)
* `npm run zodiac:status` — проверка текущего статуса
* `npm run zodiac:dry-run` — безопасный прогон (имитация отправки API)
* `npm run zodiac:workflow:check` — полная проверка пайплайна
* `npm run zodiac:publish:date:dry` — dry-run конкретной даты
* `npm run zodiac:publish:date:live` — live отправка (требует `--approved`)

## Safety Контур
1. Все публикации по умолчанию отключены или требуют явного флага `--live --approved`.
2. Система работает в режиме Dry-run, выводя планируемые действия в консоль/дашборд.
3. Отсутствуют write запросы к базе данных (всё хранится в локальных JSON файлах).
4. Запрещено пересоздавать контент с нуля, нужно переиспользовать уже написанную логику.

## Вывод
Ежедневная система уже готова. Следующие шаги могут фокусироваться на локальном улучшении качества контента (Reels/Shorts, Studio), превьюшках и подготовке к полноценному ручному подтверждению и soft launch.
